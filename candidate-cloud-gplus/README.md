# G+ / Cloudinary — эксперимент, НЕ релиз

Эта папка содержит отдельный прототип постоянного хранения G+ для исследования. Он **не подключён** к опубликованным APK или основному серверу LOLTUBE. Отдельный закрытый Render Free-сервис прошёл проверку на искусственных данных и поставлен на паузу; тестовые Cloudinary-объекты удалены. Не устанавливайте на продакшен и не храните здесь реальные данные.

## Что проверено

- Снимки трёх файлов G+ сохраняются как неизменяемые блоки с SHA-256; перед снимком SQLite WAL проходит checkpoint. HTTP-ответ на изменение задерживается до публикации и повторной проверки ревизии.
- Если две копии пытаются записать одну ревизию, проигравшая должна остановиться с 503. При ошибке хранилища не выдаётся успешный ответ. Временный файл восстановления не перезаписывает существующие файлы.
- Локальные синтетические тесты покрывают гонки, испорченный блок, недоступное хранилище, устаревший head, успешное восстановление и состояние G+ после перезапуска.
- 2026-11-03 на отдельных случайных Cloudinary-префиксах с искусственными аккаунтами и данными: создан чат и зашифрованное тестовое вложение; после SIGKILL процесса сообщения и вложение восстановились, квитанция прошла. На ускоренных часах проверено удаление шифротекста спустя 31 день после receipt, сохранность недоставленного вложения с теми же байтами и повторное восстановление после остановки. Удалены только созданные тестовые объекты.
- Медиа теперь используют отдельные для каждого вложения блоки. Очистка сначала фиксирует в durable журнале статус `deleting`, затем удаляет только принадлежащие этому вложению блоки и фиксирует tombstone; индекс остаётся для повторения после сбоя. Удаление блоков журнала или чужого вложения исключено проверкой namespace.
- Конкурентная проба Cloudinary `overwrite:false`: 24 одновременных запроса, одна новая запись и 23 `existing`; отдельная гонка двух ревизий: один победитель. Это **не** доказательство гарантированной линейризуемости у провайдера.

## Не закрыто: не включать для пользователей

1. Cloudinary описывает `overwrite:false`, но формальную гарантию атомарного конкурентного create и чтения после записи для такого журнала мы не подтвердили. Нужны гарантия провайдера либо настоящее транзакционное хранилище с fencing.
2. Очистка медиа после receipt проверена на synthetic данных и Cloudinary, однако надёжный fencing перекрывающихся экземпляров и очистка старых блоков SQLite-журнала остаются открыты. Индекс/tombstone и резервные копии метаданных намеренно сохраняются; это не гарантия уничтожения любых внешних резервов или кэша провайдера.
3. Render Free может засыпать/перезапускаться и теряет локальный диск. Его бесплатные часы и outbound bandwidth общие для workspace; при исчерпании часов все бесплатные сервисы останавливаются. Если привязан способ оплаты, дополнительный трафик может стоить денег. Нельзя запускать без проверки лимитов и защиты LOLTUBE.
4. G+ и GLINK клиенты адресуют `/gsrv-v1`, который в production сейчас отвечает 503. Новый `glink-cloud/` проверен отдельно на synthetic браузерах и настоящем Cloudinary, включая восстановление после SIGKILL; полноценная интеграция в LOLTUBE и включение маршрутов не готовы. Не меняйте production feed или `main` до общей проверки.
5. Нет реальных Android/NFC/звонков, независимого аудита, нагрузочного теста или полной проверки отказов сети и перекрывающихся деплоев. Это EXP, не `GLINK-RELEASE`.
6. Тестовая точка входа не содержит полноценного ограничения запросов/стоимости. `serve-experimental.js` работает только при `GPLUS_EXPERIMENTAL=1`, отдельном префиксе `gplus-experimental-...` и случайном `GPLUS_PREVIEW_KEY`. Без ключа HTTP-запросы к API и WebSocket отвергаются; это ограничение доступа к эксперименту, не замена защите от злоупотреблений и не готовность к публичной эксплуатации.

## Запуск тестов локально

Node 22–26, отдельно установленные зависимости из `package-lock.json`:

```sh
npm ci
npm test
```

Тесты используют только временные каталоги и искусственные объекты в памяти. Для реальных Cloudinary-проб требуется отдельный случайный префикс, учёт всех созданных объектов и очистка только их. Никогда не добавляйте ключи в Git или в логи.
