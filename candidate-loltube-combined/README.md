# GLINK + G+ + LOLTUBE — только лаборатория

`cloud-router.js` объединяет пути `/gsrv-v1/glink/*` и `/gsrv-v1/gplus/*`, G+ WSS и старые маршруты LOLTUBE в одном HTTP-сервере. Новые компоненты и пространства Cloudinary изолированы. `backup-store.js` читает строго текущий authenticated `loltube/db.json`. `ledger-backup.js` после однократного импорта сохраняет изменения в отдельный immutable-журнал и не перезаписывает старый backup; старый экземпляр не может затереть записанные в этот журнал ревизии простым overwrite прежнего объекта. `patch-upstream.py` работает только с точным публичным исходником LOLTUBE commit `16fd01082bbe312d5414bffd73f3d75024206512` (SHA-256 файла `462dc1ab2e7117dfe93ac6085f6e0390b5e8cd74efd06f83d14c1916a1c038b9`), отказывается поднимать пустую БД при недоступном резерве/журнале, блокирует успешный ответ до verified immutable revision и не подтверждает загрузку медиа на эфемерный диск. Загрузка медиа сначала проверяется и отправляется в Cloudinary вне сериализованного API, затем пользователь повторно авторизуется и метаданные фиксируются через gate.

Проверки исключительно на искусственных аккаунтах и данных: combined-router с старым LOLTUBE `/api/config`, GLINK chunk/Range, восстановление после перезапуска, регистрация/чат/медиа G+, двусторонний WSS и повторное восстановление; полный исходный LOLTUBE + mock Cloudinary: успешный login и запись до ответа, SIGKILL, восстановление после поздней записи в старый backup, отказ media/ledger с 503, boot при недоступном storage без стирания и параллельный API во время медленной загрузки. На настоящем Cloudinary в случайном отдельном префиксе два конкурирующих synthetic LOLTUBE writer дали одного победителя, данные победителя восстановлены; 6 тестовых объектов удалены. `fake-cloudinary-lab.cjs` — только synthetic mock, в production запускать нельзя. Отдельно новый G+ retention прошёл тест на настоящем Cloudinary на случайных искусственных данных; тестовые объекты очищены.

**Не развёртывать как production:** гарантия provider-level CAS/fencing отсутствует. При первом запуске лаборатория импортирует старый backup без ожидания старого экземпляра; для production нужен проверенный безопасный cutover и последняя сохранённая версия, иначе изменения старого экземпляра до импорта могут потеряться. Не доказаны no-overlap drain и отсутствие активных загрузок LOLTUBE. Не проверены общая защита от исчерпания Cloudinary и Render лимитов/расходов, эксплуатационная очистка старых ревизий, реальная нагрузка/большие медиа, полноценная сборка Render и Android/NFC/звонки. G+ не готов как RELEASE; аватар, редактирование участников групп и устойчивые входящие фоновые звонки отсутствуют. Не публиковать feeds/APK до устранения причин и проверки с владельцем.

Node 24 и зависимости `express`, `better-sqlite3`, `cloudinary`, `ws` берутся извне workspace. Тесты запускаются `node --test loltube-combined/*.test.js` с `NODE_PATH` к временным лабораторным зависимостям. Для полного server-теста `LOLTUBE_UPSTREAM_DIR` должен указывать на изолированную копию публичного исходника без реальных данных. Логи не должны содержать ключи, токены, подписанные URL или имена пользовательских файлов.
