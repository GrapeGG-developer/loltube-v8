# GLINK + G+ + LOLTUBE — только лаборатория

`cloud-router.js` объединяет пути `/gsrv-v1/glink/*` и `/gsrv-v1/gplus/*`, G+ WSS и старые маршруты LOLTUBE в одном HTTP-сервере. Новые компоненты и пространства Cloudinary изолированы. `backup-store.js` адресует строго текущий authenticated `loltube/db.json` и проверяет сохранённый результат. `patch-upstream.py` работает только с точным публичным исходником LOLTUBE commit `16fd01082bbe312d5414bffd73f3d75024206512` (SHA-256 файла `462dc1ab2e7117dfe93ac6085f6e0390b5e8cd74efd06f83d14c1916a1c038b9`), отказывается поднимать пустую БД при недоступной резервной копии, блокирует успешный ответ до backup/readback и не подтверждает загрузку медиа на эфемерный диск.

Проверки исключительно на искусственных аккаунтах и данных: combined-router с старым LOLTUBE `/api/config`, GLINK chunk/Range, восстановление после перезапуска, регистрация/чат/медиа G+, двусторонний WSS и повторное восстановление; полный исходный LOLTUBE + mock Cloudinary: успешный login и backup до ответа, SIGKILL, восстановление, отказ media/cloud backup с 503 и boot при недоступном backup без стирания. `fake-cloudinary-lab.cjs` — только synthetic mock, в production запускать нельзя. Отдельно новый G+ retention прошёл тест на настоящем Cloudinary на случайных искусственных данных; тестовые объекты очищены.

**Не развёртывать как production:** проверенный provider-level CAS/fencing отсутствует; старый Render экземпляр может после переключения перезаписать backup; нет доказанного no-overlap drain и способа проверить все активные загрузки LOLTUBE. Общая защита от исчерпания Cloudinary и Render лимитов/расходов, нагрузка и поведение больших медиа, полноценная сборка Render, реальные Android/NFC и устойчивые звонки не проверены. Очередь API LOLTUBE сериализует запрос целиком, включая загрузку видео, что может блокировать другие запросы. G+ не готов как RELEASE; аватар, редактирование участников групп и устойчивые входящие фоновые звонки отсутствуют. Не публиковать feeds/APK до устранения причин и проверки с владельцем.

Node 24 и зависимости `express`, `better-sqlite3`, `cloudinary`, `ws` берутся извне workspace. Тесты запускаются `node --test loltube-combined/*.test.js` с `NODE_PATH` к временным лабораторным зависимостям. Для полного server-теста `LOLTUBE_UPSTREAM_DIR` должен указывать на изолированную копию публичного исходника без реальных данных. Логи не должны содержать ключи, токены, подписанные URL или имена пользовательских файлов.
